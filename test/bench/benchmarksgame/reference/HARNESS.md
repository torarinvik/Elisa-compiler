# Reference harness hardening

`build_refs.sh` removes each requested task's previous Rust and Zig executables
before rebuilding. Cargo is invoked with `--locked` only; a lockfile mismatch is
a build failure. The expected missing Zig sources for `regexredux` and `revcomp`
are reported explicitly. A build failure removes its output executable.

`run_compare.sh` requires a runnable Rust and Zig binary for the requested task,
and validates an optional Elisa path when supplied. It rejects `regexredux` and
`revcomp` because this repository has no Zig comparator for those tasks. `RUNS`
and `N` must be positive decimal integers (`N=official` selects the documented
official size). For mandelbrot, `N` must also be divisible by eight, matching
the current Zig port's output-width restriction.

Every output from every repetition is checked against a canonical oracle before
its time is considered. Small-size oracle files are already in `expected/` and
are required. For other sizes, add either
`expected/<bench>-<N>-output.txt` or
`expected/<bench>-<N>-output.sha256`. A SHA file contains one 64-digit hash of
the exact expected stdout bytes. The comparison stops before launching programs
if the oracle is absent or malformed; it never falls back to agreement between
the implementations.

The stdin workloads use FASTA generated by the built Rust `fasta` executable.
That data is checked against the canonical FASTA oracle for the same size. A
sidecar next to the cached data records the size, FASTA executable SHA-256,
oracle SHA-256, input byte count, and input SHA-256. A missing, stale, altered,
or mismatched cache is regenerated and checked before use.

Only the small-size output oracles are currently present in this copy. Official
and arbitrary-size comparisons therefore require independently obtained
canonical output oracles; stdin tasks additionally require a FASTA oracle for
their input size. The official-size figures in `RESULTS.md` predate these strict
checks and are historical one-run observations, not outputs validated by this
hardened runner. The harness still compares different benchmark programs, not
algorithmically normalized implementations; threading, allocator, and library
differences remain part of those timings.
